SpacePay 开放平台

用一套简洁的 HTTP API 接收付款、发起退款并接收实时事件。所有金额以整数分存储，接口返回同时给出小数金额。

本环境的余额为虚拟资金，不接入真实银行卡或支付渠道，结算出款为模拟流程。接口行为、签名与幂等语义与生产实现一致，可用于完整联调。
接口地址
鉴权方式Authorization: Bearer sp_live_… 或 X-API-Key
数据格式JSON（Content-Type: application/json），UTF-8
金额字段 amount 使用十进制字符串（如 "12.34"）；返回同时包含 amount_cents
时间毫秒时间戳（UNIX epoch, ms）

快速开始

1
开户：在 商户后台 提交入驻申请，审核通过后账户角色变为商户。
2
创建密钥：在商户后台「API 密钥」中创建 sp_live_…。密钥只在创建时显示一次，服务端只保存哈希。
3
发起支付：调用创建支付接口，把返回的 checkout_url 交给付款人；付款完成会收到 payment.succeeded Webhook。

鉴权

所有 /api/v1/* 请求都需要 API Key。密钥由 sp_live_、sp_test_ 前缀、Key ID 与 Secret 组成；Secret 只在创建时返回一次，之后无法再次读取。

curl
curl https://your-domain/api/v1/balance \
  -H "Authorization: Bearer sp_live_xxxxxxxxxxxxxxxx_yyyyyyyyyyyyyyyyyyyyyyyy"

也可以使用 X-API-Key 请求头。请把密钥保存在服务端环境变量中，不要放进浏览器、移动端或 Git 仓库。怀疑泄露时在商户后台立即吊销并重新创建。

创建支付

POST/api/v1/payments
参数类型说明
amountstring必填。金额，如 "12.34"，最多 2 位小数，必须大于 0
currencystring可选，默认 USD
referencestring你的订单号，同一商户内唯一；重复使用且金额相同会返回同一支付单
descriptionstring商品或服务描述，付款人可见
customer_emailstring限定付款人；设置后其他账户不能支付该单
metadataobject自定义键值，序列化后不超过 2KB
success_urlstring支付成功后跳转地址
cancel_urlstring付款人取消后跳转地址
请求
curl -X POST https://your-domain/api/v1/payments \
  -H "Authorization: Bearer $SPACEPAY_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-3b7d-4c55-9a10-2f8e7d6c5b4a" \
  -d '{
    "amount": "12.34",
    "reference": "order-2026-0001",
    "description": "拿铁两杯",
    "metadata": { "sku": "latte" },
    "success_url": "https://shop.example/paid"
  }'

查询支付

GET/api/v1/payments/:id

:id 接受 pay_1 或 1。响应包含该支付单的全部退款记录。

支付列表

GET/api/v1/payments?limit=20&starting_after=pay_100&status=SUCCEEDED

按创建时间倒序返回。使用 next_starting_after 翻页，limit 最大 100。

退款

POST/api/v1/payments/:id/refund
参数类型说明
amountstring可选，默认退剩余全部；不能超过可退金额
reasonstring退款原因，付款人可见
curl
curl -X POST https://your-domain/api/v1/payments/pay_1/refund \
  -H "Authorization: Bearer $SPACEPAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount":"2.34","reason":"部分退单"}'

退款从商户可结算余额退回付款人钱包；余额不足时返回 INSUFFICIENT_MERCHANT_BALANCE。

Webhook

在商户后台填写 HTTPS 回调地址后，以下事件会以 POST 方式推送。每个请求体都是完整事件对象。

事件触发时机
payment.succeeded付款人完成支付
payment.refunded商户或运营发起退款后
事件体
{
  "id": "evt_9f8e7d6c5b4a3210",
  "type": "payment.succeeded",
  "created": 1762800000,
  "data": {
    "id": "pay_1",
    "reference": "order-2026-0001",
    "amount_cents": 1234,
    "status": "SUCCEEDED",
    "metadata": { "sku": "latte" }
  }
}

请求头：

X-SpacePay-Event事件类型
X-SpacePay-Delivery事件 ID，重试时保持不变，可用于去重
X-SpacePay-Signaturet=时间戳,v1=签名

你的服务端应在 10 秒内返回 2xx。非 2xx 或超时会按 1 分钟、5 分钟、30 分钟、2 小时、6 小时 重试，共 6 次；最终失败可在商户后台手动重投。务必以 事件 ID 去重，并先校验签名再处理业务。

签名校验

签名 = HMAC-SHA256(webhook_secret, 时间戳 + "." + 原始请求体)，十六进制。请使用原始字节计算，不要先反序列化再重新序列化。

Node.js
const crypto = require('crypto');

function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  const expected = crypto.createHmac('sha256', secret)
    .update(`${parts.t}.${rawBody}`)
    .digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));
}
Python
import hmac, hashlib

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    expected = hmac.new(secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])

结账流程

  1. 你的服务端调用创建支付，得到 checkout_url。
  2. 把付款人浏览器跳转到该地址。付款人登录 SpacePay 并输入 6 位支付 PIN 完成付款。
  3. 你的服务端收到 payment.succeeded Webhook，校验签名与事件 ID 后发货。
  4. 付款人浏览器跳转到 success_url。

不要只依赖用户跳回 success_url 判断支付成功——跳转可能被中断；以 Webhook 为准，必要时再调用查询接口确认。

错误码

错误响应统一为：

响应
{ "ok": false, "error": "可读说明", "code": "MACHINE_CODE", "request_id": "req_…" }
HTTPcode说明
401INVALID_API_KEY密钥缺失、格式错误、已吊销或 Secret 不匹配
403MERCHANT_INACTIVE商户未通过审核或已被暂停
404PAYMENT_NOT_FOUND支付单不存在或不属于该商户
400AMOUNT_*金额缺失、格式、精度、为 0 或超出上限
409REFERENCE_CONFLICT订单号已用于金额不同的支付
409PAYMENT_NOT_REFUNDABLE只有成功支付可以退款
400INSUFFICIENT_MERCHANT_BALANCE可结算余额不足
422IDEMPOTENCY_KEY_REUSED同一幂等键用于不同参数
429RATE_LIMITED超过每个 Key 每分钟的请求数

排查问题时请提供响应里的 request_id，它同时出现在服务端访问日志中。

限流与幂等

限流：每个 API Key 每分钟 120 次请求，超出返回 429。

幂等：资金类 POST 支持 Idempotency-Key 请求头（8–255 位字母、数字或 - _ : .）。相同 Key + 相同参数在 24 小时内重放原响应，并返回 Idempotent-Replayed: true；参数不同返回 422。网络超时后请用同一个键重试，不要生成新键。

订单号幂等：reference 相同且金额一致的创建请求会返回同一笔支付，适合作为业务侧的去重键。
