密钥与安全

API Key 是商户服务端的凭据，等同于你的账户权限。请按下面的方式保管、轮换和排查。

密钥格式

sp_live_<key_id>_<secret>
sp_test_<key_id>_<secret>

key_id  16 位十六进制，用于索引
secret  32 位随机串，只在创建时返回一次

服务端只保存 secret 的 SHA-256 哈希，无法再次读出。丢失后只能吊销并重新创建。

保管

  • 放在服务端环境变量或密钥管理服务中，例如 SPACEPAY_KEY。
  • 不要写进浏览器代码、移动端包体、Git 仓库、日志或错误上报。
  • 不同环境（测试 / 生产）、不同服务使用不同的 Key，便于单独吊销。
  • 当前 sp_test_ 与 sp_live_ 的行为一致，仅用于区分环境标签；接入真实支付时会区分沙箱与生产。

轮换与吊销

创建新密钥

商户后台 →「API 密钥」→ 创建，复制新密钥并更新服务端配置。

验证新密钥

调用 GET /api/v1/balance 确认新密钥可用。

吊销旧密钥

确认没有流量后吊销旧密钥，吊销立即生效。

!怀疑密钥泄露时不要等待：立即吊销，创建新密钥，并检查商户后台的 API 请求日志与支付记录。

Webhook 签名密钥

每个商户有一个 webhook_secret，用于计算 X-SpacePay-Signature。在商户后台「Webhook」页可以重置：

  • 重置后旧密钥立即失效，新密钥只显示一次。
  • 你的服务端需要同时更新密钥；更新期间可以短暂接受旧签名完成切换。
  • 签名校验必须使用原始请求体，并用常量时间比较。

传输与网络

  • 所有接口必须通过 HTTPS 访问；HTTP 请求会被重定向或拒绝。
  • Webhook 地址必须是 HTTPS，且不能指向本机、内网或链路本地地址；投递前会解析域名做二次校验。
  • 不要在 Webhook 地址中使用会跳转到内网的短链或代理。

支付安全

  • 金额由服务端根据订单计算，不要直接使用前端传入的金额。
  • 付款人必须登录并输入支付 PIN；PIN 连续错误会锁定。
  • customer_email 可以限定付款人，适合会员或定向支付场景。
  • 以 Webhook 或查询接口确认支付结果，不要信任浏览器跳转。

日志与排查

  • 服务端日志会记录请求编号 request_id，不会记录密钥、PIN、密码与签名密钥。
  • 提交工单或在商户后台排查时，提供 request_id 与发生时间，不要粘贴完整密钥。
  • 商户后台可以查看最近 100 条 API 请求日志，用于确认调用方与状态码。
!本环境是虚拟资金环境。若将来接入真实资金，必须由持牌支付机构处理资金流，并完成相应的合规与安全审计。
