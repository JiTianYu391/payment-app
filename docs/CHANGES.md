# SpacePay 改造说明

日期：2026-11-07。分支：`claude/spacepay-system-upgrade-z2ugnt`。

## 1. 改了什么、为什么

| 方面 | 改动 | 原因 |
| --- | --- | --- |
| 品牌 | 系统定名 SpacePay；新增符号、字标组合（浅色 / 深色）与自适应 favicon（`public/brand/`，说明见 `docs/brand.md`）；页面标题、界面、文档统一使用新名称 | 需求一 |
| 金额 | 新增 `src/money.js`：输入按字符串逐位解析为整数分，乘除用 BigInt 四舍五入；替换全部 `Math.round(parseFloat(x) * 100)` 与利息 / 分红中的浮点乘法 | `parseFloat` 会产生如 `1.005 → 100.49999` 的误差；需求五 |
| 账务 | 新增复式账本 `ledger_entries`（只追加，每个 journal 借贷之和为 0）；所有余额变动集中到 `wallet.applyCash`；升级时为已有余额补期初分录 | 参考 Stripe Ledger / Square Books；能证明每一分钱的去向，并支撑对账 |
| 并发 | 扣款改为条件更新 `UPDATE … WHERE balance_cents >= ?`，与流水、分录同事务；SQLite 写锁冲突时退避重试；事务支持嵌套 | 原转账先读余额、再在事务外判断，付款不在事务内，并发下可能透支 |
| 幂等 | 资金类 POST 支持 `Idempotency-Key`（24 小时，参数摘要比对，处理中 409，异参 422）；下单接口同时接受请求头 | 需求五；参考 Stripe / PayPal |
| 状态机 | 支付、提现、账户三种状态机，非法迁移返回 409；退款用乐观锁防并发叠加 | 交易状态清晰可审计 |
| 功能 | 退款（部分 / 全额，超额与零金额拒绝）；提现（申请 → 财务审核 → 出款 / 驳回退回，在途清算科目，审核人不能审核自己）；账户冻结 | 需求二 |
| 二次确认与操作日志 | 退款、冻结 / 解冻、调整角色、提现申请与审核：服务端返回 428 + 摘要 + 一次性令牌（绑定操作人、动作、参数，5 分钟有效），确认后执行；全部写入只追加的 `operation_logs`（含被拒绝的尝试） | 需求二；确认在服务端强制，不依赖前端 |
| 权限 | 用户 / 只读访客 / 财务 / 管理员四级（`src/rbac.js`），`ADMIN_EMAILS` 引导管理员 | 需求二；参考 Stripe 预置角色 |
| 报表 | 交易多维筛选、排序、分页、筛选合计；导出 CSV（UTF-8 BOM、防公式注入）与 Excel（自写 xlsx 生成器，金额为数值单元格、格式 `#,##0.00`、首行冻结），单次上限 1 万行 | 需求二 |
| 口径 | `src/metrics.js` 统一定义收入、支出、投资往来、投资收益；钱包统计、交易合计、运营概览、业绩计算共用；接口返回统计周期 | 需求三：同一指标在不同页面口径一致 |
| 健壮性 | 统一错误格式（用户可读 `error` + `code` + `request_id`，日志记录完整堆栈）；输入校验模块；结构化 JSON 日志（敏感字段打码）；请求超时 503；邮件投递超时 + 重试 + 降级；健康检查报告组件状态；优雅停机 | 需求五 |
| 界面 | 重写样式与前端：设计令牌（间距、字号、圆角、颜色），中性灰 + 单一品牌蓝，浅色 / 深色；去掉渐变、大圆角、emoji、营销文案；表格表头固定、数字右对齐、等宽数字、千分位与货币符号、状态徽标；图表带标题、单位、图例、坐标轴标签、统计周期与悬停数值，配色经色弱校验；新增运营后台 | 需求三、四 |
| 安全 | 前端对所有用户输入的文本做 HTML 转义（运营后台会展示其他用户填写的商户名、备注） | 原前端直接拼接 innerHTML，存在 XSS 风险 |

### 顺带修复的缺陷

1. JSON 降级后端在 `SELECT 列 … ORDER BY 未选列` 时先投影后排序，排序失效（如「取最后一笔流水」取错行）。
2. `/api/stats` 把卖出（正数）按绝对值计入支出，把买入也算作支出；现按 `metrics.js` 口径计算。
3. 定存到期 / 提前支取时，本金与利息合并记为一笔「利息」，导致利息收入虚高；现在拆为「定存兑付」（本金）与「利息」两笔。
4. 定存提前支取没有并发保护，可能重复支取；现改为条件更新。
5. 非演示模式下请求验证码时并不发送，却返回「已发送」；现在未配置投递地址时返回 503。

## 2. 兼容性（不破坏的部分与行为变化）

**保持不变**：全部已有接口的路径、方法、请求字段和响应字段；`{ ok, error }` 错误格式（只追加 `code`、`request_id`）；`/api/transactions` 的 `type`、`category`、`q`、`from`、`to`、`limit`、`offset` 参数和 `total` 字段（仍为本人全部流水数）、默认返回最近 50 条；下单的 body `idempotency_key` 与重复提交返回 `duplicate: true`；SQLite / JSON 两种存储及旧版 JSON 自动迁移。

**行为变化（需要知晓）**：

| 变化 | 影响 |
| --- | --- |
| 金额超过 2 位小数（如 `1.005`）现在返回 400，此前四舍五入 | 前端与常规调用不受影响 |
| 交易筛选参数取值非法（如未知 `type`）返回 400，此前被忽略 | 便于发现调用错误 |
| `/api/stats` 的 `income_cents`、`expense_cents` 数值按新口径计算（见缺陷 2） | 数值会变化，字段不变 |
| 新的定存兑付记为 `FD_REDEEM` + `INTEREST` 两笔（历史数据不改） | 按 `type=INTEREST` 统计的调用方只会看到利息 |
| 冻结账户的转账 / 付款 / 提现 / 下单 / 充值返回 423 `ACCOUNT_FROZEN`；向冻结账户转账返回 400 | 新功能 |
| 演示重置会留下一条「演示重置」流水（账本只追加）；有待审核提现时拒绝重置 | 保证对账成立 |
| 未知 `/api/*` 路径返回 JSON 404，此前返回首页 HTML | — |
| 非演示模式请求验证码需要配置 `MAIL_WEBHOOK_URL`，否则返回 503 | 见缺陷 5 |
| 新增「提现」功能。原界面写的是「不可提现」；现在可以提现，但为模拟出款，文案已同步 | 见假设 3 |
| `src/server.js` 改为导出 `{ createApp, start }`；`app.js` 调用 `start()`；`node src/server.js` 仍可直接启动 | 仅影响直接 `require` 该文件的代码 |

**新增依赖**：无。Excel 导出、图表、日志、重试均为自写，ZIP 的 CRC32 使用 Node 内置 `zlib.crc32`。

## 3. 假设

1. 支付为「即时成功」模型（扣款即结算），不设授权 / 请款两阶段；退款由财务或管理员在后台发起，系统中没有独立的商户端。
2. 只支持 USD 单一币种；账本记录了 `currency` 字段，便于以后扩展。
3. 提现保持演示性质：资金进入「提现在途」科目，财务批准后转入「外部出款」科目，不连接真实银行；单笔上限 `WITHDRAW_MAX_CENTS`（默认 $500）。
4. 「商户」筛选按交易上的商户名称模糊匹配；运营后台另提供用户邮箱筛选。
5. 「只读访客」指能查看运营后台、但不能导出或操作的内部人员，不是未登录访客。
6. 冻结账户仍可登录查看，并可接收退款与提现驳回退回，但不能主动转出，也不能接收转账。
7. 导出时间统一用 UTC；界面按浏览器本地时区显示。
8. 「等宽数字字体」用 `font-variant-numeric: tabular-nums` 实现（各位数字等宽、纵向对齐），正文不改用等宽字体。
9. 幂等键为可选（兼容旧客户端）；新前端对每次资金提交都会携带。只有成功（2xx）的结果会被保存；失败的请求在事务内回滚，可以用同一个键重试。

## 4. 未覆盖的部分

- 真实支付通道、KYC / 反洗钱、银行出款与渠道对账文件（Adyen 结算报表那一类的外部对账）。
- 多实例部署：二次确认令牌的「已使用」记录和限流计数保存在进程内存；JSON 降级后端的幂等不支持多进程。多实例部署需要换成共享存储（如 Redis 或数据库）。
- 运营后台的用户、支付、提现、操作日志列表在内存中筛选分页，适合演示规模；数据量大时应改为 SQL 分页。交易列表在 SQLite 后端已经由数据库完成筛选与分页。
- 报表列自定义、定时报表、导出任务排队；单次导出上限 1 万行。
- 前端浏览器自动化测试尚未纳入 `npm test` 和 CI（用 Playwright 手动走查，见下文）。
- 行情模型用浮点对数收益率生成价格，结果取整为整数分；收益率、占比等百分比为展示用浮点数。这些都不参与金额记账。
- 会话令牌仍保存在 `localStorage`（沿用原设计），没有改成 HttpOnly Cookie。
- 演示重置仍会删除本账户的流水明细（原有功能）；账本分录保留，并通过冲正记录保持平衡。
